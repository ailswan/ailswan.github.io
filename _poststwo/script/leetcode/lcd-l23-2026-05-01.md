# PPT 1 — Title Slide

Hello everyone.

Today I'd like to talk about another critical graph pattern:

**Graph Shortest Path.**

Many graph interview questions ultimately ask the same thing:

```text
What is the cheapest way
to get from A to B?
```

Sometimes the cost is:

* Number of steps
* Distance
* Time
* Effort
* Price

The challenge is choosing the correct shortest path algorithm.

The key idea is:

**Different edge cost models require different shortest path algorithms.**

---

# PPT 2 — Core Framework

When solving shortest path problems, I ask five questions:

```text
Is the graph weighted?

Are weights non-negative?

Do we need one source or all pairs?

Can weights be negative?

Do all edges have equal cost?
```

These questions determine the algorithm.

```text
Unweighted → BFS

Non-negative weighted → Dijkstra

0/1 weights → 0-1 BFS

Negative weights → Bellman-Ford

All pairs → Floyd-Warshall
```

The key idea is:

**Choose the algorithm based on edge weights.**

---

# PPT 3 — BFS for Unweighted Graphs

Let's start with the simplest case.

Suppose every edge costs the same.

For example:

```text
A → B → C
```

Every move costs one step.

BFS explores nodes level by level:

```text
Distance 0

Distance 1

Distance 2

Distance 3
```

The first time we visit a node,
we have found its shortest path.

Common examples:

* Word Ladder
* Rotting Oranges
* Walls and Gates
* Grid shortest path

The key idea is:

**BFS is shortest path for unweighted graphs.**

---

# PPT 4 — Multi-Source BFS

Sometimes we don't have one starting point.

We have many.

For example:

```text
Rotting Oranges

Walls and Gates

Distance to Nearest Zero
```

Instead of starting BFS from one node,
we start from all source nodes simultaneously.

All sources enter the queue with distance zero.

Then BFS expands outward.

This guarantees every node finds its nearest source.

The key idea is:

**Multi-source BFS computes nearest-source distance efficiently.**

---

# PPT 5 — Dijkstra Algorithm

Now let's introduce weighted graphs.

Suppose edges have different costs:

```text
A → B cost 1

A → C cost 5

B → C cost 1
```

The shortest path isn't necessarily the fewest steps.

Instead we want minimum total cost.

Dijkstra solves this problem.

It always expands the node with the currently smallest known distance.

To do this efficiently,
it uses a min heap.

The key idea is:

**Dijkstra always explores the cheapest candidate first.**

---

# PPT 6 — Dijkstra Example

Consider:

```text
A → B (1)

A → C (5)

B → C (1)
```

We start at A.

Initially:

```text
A = 0

B = ∞

C = ∞
```

Visit A.

Update:

```text
B = 1

C = 5
```

Next, visit B because it has smaller distance.

Then:

```text
C = min(5, 1 + 1)

C = 2
```

The shortest path becomes:

```text
A → B → C
```

The key idea is:

**Distances improve through edge relaxation.**

# PPT 7 — Network Delay Time

One famous LeetCode problem is:

```text
Network Delay Time
```

A signal starts from one node.

How long until every node receives it?

This is a classic:

```text
Single Source

Weighted Graph

Non-negative Weights
```

Therefore:

```text
Dijkstra
```

After running Dijkstra:

```text
Maximum shortest distance
```

becomes the answer.

The key idea is:

**Network Delay Time is a textbook Dijkstra problem.**

---

# PPT 8 — 0-1 BFS

Some graphs have a special property.

Edge weights are only:

```text
0

1
```

Examples:

* Minimum obstacle removal
* Binary maze problems
* Edge reversal problems

Instead of Dijkstra,
we can use:

```text
0-1 BFS
```

Using a deque:

```text
Weight 0 → push front

Weight 1 → push back
```

This maintains increasing distance order.

The key idea is:

**0-1 BFS is faster than Dijkstra when weights are only 0 and 1.**

---

# PPT 9 — Bellman-Ford

Now let's consider negative weights.

Example:

```text
A → B = 5

B → C = -10

A → C = 2
```

Dijkstra no longer works correctly.

Instead we use:

```text
Bellman-Ford
```

Bellman-Ford repeatedly relaxes all edges.

For:

```text
n nodes
```

we relax:

```text
n − 1 times
```

It can also detect:

```text
Negative Cycles
```

The key idea is:

**Bellman-Ford handles negative weights safely.**

---

# PPT 10 — Floyd-Warshall

Sometimes we need:

```text
Shortest path between every pair of nodes.
```

Not just one source.

Examples:

```text
All city-to-city distances

Network reachability

Small graph analysis
```

Floyd-Warshall uses dynamic programming.

Transition:

```text
dist[i][j]

=

min(

dist[i][j],

dist[i][k] + dist[k][j]

)
```

Try every node as an intermediate stop.

The complexity is:

```text
O(n³)
```

The key idea is:

**Floyd-Warshall computes all-pairs shortest paths.**

---

# PPT 11 — Shortest Path vs MST

A very common interview confusion is:

```text
Shortest Path

vs

Minimum Spanning Tree
```

Shortest Path asks:

```text
How do I get from A to B cheaply?
```

MST asks:

```text
How do I connect all nodes cheaply?
```

Shortest path algorithms:

```text
BFS

Dijkstra

Bellman-Ford
```

MST algorithms:

```text
Prim

Kruskal
```

They solve different problems.

The key idea is:

**Shortest path minimizes route cost, MST minimizes total connection cost.**

# PPT 12 — Senior-Level Explanation

At a senior level, shortest path is not about memorizing algorithms.

It is about understanding the graph model.

I always ask:

```text
What does a node represent?

What does an edge represent?

What does the weight represent?
```

Then I classify the graph:

```text
Unweighted?

Weighted?

Negative weights?

Single source?

All pairs?
```

Once those questions are answered,
the algorithm becomes obvious.

The final insight is:

**Shortest path is really a cost optimization problem over a graph.**

If you can identify the cost model,

you can identify the correct algorithm.

Thank you.

**(PPT: Choosing the Right Shortest Path Algorithm)**
