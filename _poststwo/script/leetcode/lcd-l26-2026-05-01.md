 # 🎬 LCA (Lowest Common Ancestor) 

---

# PPT 1 — Title Slide

Hello everyone.

Today I'd like to walk through another important tree pattern:

**Lowest Common Ancestor, or LCA.**

LCA is one of the most frequently asked tree problems in coding interviews.

But more importantly, LCA is not just a standalone problem.

It is a building block for:

* Tree distance calculations
* Path queries
* Ancestor relationships
* Binary lifting
* Advanced tree algorithms

The core idea is:

```text
Find the lowest node
that contains both target nodes
in its subtree
```

The key idea is:

**LCA identifies where two paths in a tree meet.**

---

# PPT 2 — What Problem Are We Solving?

Let's start with the definition.

Given two nodes:

```text
p
q
```

The Lowest Common Ancestor is:

```text
The lowest node
that has both p and q
as descendants.
```

A node can be a descendant of itself.

This creates an important edge case.

If one node is already an ancestor of the other:

```text
5
|
4
```

Then:

```text
LCA(5,4) = 5
```

The key idea is:

**The LCA is where two search paths first come together.**

---

# PPT 3 — Basic Example

Consider this tree:

```text
        3
       / \
      5   1
     / \ / \
    6  2 0  8
      / \
     7   4
```

If:

```text
p = 5
q = 1
```

Then the answer is:

```text
3
```

because 5 is in the left subtree and 1 is in the right subtree.

Another example:

```text
p = 5
q = 4
```

The answer is:

```text
5
```

because 5 is already an ancestor of 4.

The key idea is:

**The LCA is the first split point when tracing both nodes upward.**

# PPT 4 — LCA in a Binary Tree

For a general binary tree, there is no ordering information.

So we must search both subtrees.

The recursive logic is surprisingly simple.

For each node:

```text
If node is null:
    return null

If node is p or q:
    return node
```

Then recursively search:

```text
left subtree
right subtree
```

Three situations can happen:

If both sides return a node:

```text
left != null
right != null
```

then the current node is the LCA.

If only one side returns a node:

```text
left != null
right == null
```

or vice versa,

we simply return that result upward.

The key idea is:

**The LCA is the first node that receives results from both sides.**

---

# PPT 5 — Why Postorder Traversal Works

Many candidates memorize the solution but don't understand why it works.

The reason is:

The parent cannot decide whether it is the LCA until it knows what happened in both children.

It needs answers from:

```text
left subtree
right subtree
```

before making a decision.

This naturally becomes:

```text
Left
Right
Root
```

which is postorder traversal.

At every node we ask:

```text
Did left find a target?

Did right find a target?
```

If both answers are yes,

the current node becomes the split point.

The key idea is:

**LCA is a bottom-up problem, so postorder traversal is the natural solution.**

---

# PPT 6 — LCA in a Binary Search Tree

Now let's consider a BST.

A BST provides additional information:

```text
left < root < right
```

This changes everything.

Suppose:

```text
p = 2
q = 8
root = 6
```

Since:

```text
2 < 6 < 8
```

the paths split at 6.

Therefore:

```text
LCA = 6
```

If both nodes are smaller than the current node:

```text
move left
```

If both are larger:

```text
move right
```

Otherwise:

```text
current node is the answer
```

The key idea is:

**In a BST, the LCA is the value where the two search paths diverge.**

---

# PPT 7 — LCA with Parent Pointers

Sometimes each node has:

```python
node.parent
```

Instead of searching downward,

we can move upward.

One simple solution is:

Store all ancestors of p in a set.

Then walk upward from q.

The first ancestor found in the set is the LCA.

There is also a more elegant solution.

Use two pointers.

This is almost identical to Linked List Intersection.

When a pointer reaches the root:

```text
switch to the other starting node
```

Eventually both pointers travel the same total distance and meet at the LCA.

The key idea is:

**Parent pointers transform LCA into an ancestor-intersection problem.**

---

# PPT 8 — LCA with Missing Nodes

A very common follow-up question is:

```text
What if p or q
does not exist?
```

The standard solution assumes both nodes exist.

But consider:

```text
p exists
q missing
```

The normal algorithm may incorrectly return p.

A safer solution tracks:

```text
Did we find p?

Did we find q?
```

Only if both are found do we return the LCA.

Otherwise:

```text
return null
```

The key idea is:

**Always verify assumptions when the problem statement changes.**

---

# PPT 9 — Binary Lifting

Now let's talk about a more advanced scenario.

Suppose:

```text
100,000 nodes

100,000 LCA queries
```

Running DFS for every query would be too slow.

Instead we preprocess.

The most common technique is:

```text
Binary Lifting
```

For every node we store:

```text
2^0 ancestor
2^1 ancestor
2^2 ancestor
2^3 ancestor
...
```

Then during a query we jump upward in powers of two.

Complexity becomes:

```text
Preprocessing:
O(n log n)

Query:
O(log n)
```

The key idea is:

**Binary Lifting trades preprocessing for much faster queries.**

# PPT 10 — LCA Applications

LCA appears in many problems beyond simply finding ancestors.

For example:

Distance between two nodes.

The formula is:

```text
distance(u,v)

=

depth(u)
+
depth(v)
-
2 * depth(lca)
```

LCA is also used for:

* Path sum queries
* Tree relationship queries
* Ancestor checks
* Deepest leaves
* Binary lifting systems

Many advanced tree problems secretly become LCA problems.

The key idea is:

**LCA is often a building block rather than the final goal.**

# PPT 11 — Common Mistakes

There are several common interview mistakes.

Mistake number one:

Using BST logic on a normal binary tree.

BST shortcuts only work when ordering exists.

Mistake number two:

Comparing values instead of node references.

This breaks when duplicate values exist.

Mistake number three:

Ignoring missing-node scenarios.

Mistake number four:

Not recognizing when binary lifting is needed for repeated queries.

The key idea is:

**Most LCA mistakes come from misunderstanding the tree model.**

# PPT 12 — Senior-Level Explanation and Closing Insight

At a senior level, I would explain LCA like this.

LCA is fundamentally a tree relationship problem.

The first thing I identify is:

```text
What type of tree
am I dealing with?
```

If it is:

```text
General Binary Tree
```

I use postorder recursion.

If it is:

```text
Binary Search Tree
```

I use value ordering.

If nodes have:

```text
Parent Pointers
```

I move upward.

If there are:

```text
Many Queries
```

I use Binary Lifting.

The final insight is:

**LCA is not about memorizing one recursive template.**

**It is about understanding how information flows through a tree and identifying where two paths meet.**

If you can explain:

* Why postorder works
* Why BST is different
* How parent pointers change the solution
* When binary lifting is needed

then you understand LCA at an interview-ready level.

Thank you.
