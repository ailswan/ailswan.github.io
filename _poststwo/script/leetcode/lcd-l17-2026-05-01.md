 # 🎬 Heap / Priority Queue — 4-5 Minute YouTube Script

## PPT 1 — Title Slide

Hello everyone.

Today I'd like to walk through another important LeetCode pattern:

**Heap, also known as Priority Queue.**

Heap is one of the most frequently tested data structures in coding interviews because it helps us efficiently find the current best candidate.

The candidate could be the smallest number, the largest number, the highest frequency element, the closest point, or the next task that should be processed.

The core idea is simple:

Maintain a dynamic set of candidates and always be able to retrieve the highest-priority candidate efficiently.

---

## PPT 2 — What Problem Does Heap Solve?

When should we think about using a heap?

Usually when the problem asks for:

* Top K elements
* Kth largest or smallest
* Merge K sorted lists
* Streaming median
* Scheduling tasks
* Shortest path problems like Dijkstra

A useful interview signal is this:

If the problem repeatedly asks for the current minimum or maximum element while new elements are continuously added, a heap is often the right solution.

The key question I always ask is:

**What is the priority?**

Because a heap is really just a priority queue.

---

## PPT 3 — Min Heap vs Max Heap

A min-heap keeps the smallest element on top.

A max-heap keeps the largest element on top.

In Python, heapq only provides a min-heap.

To simulate a max-heap, we simply store negative values.

For example:

```python
heapq.heappush(heap, -value)
```

A common interview shortcut is:

If I need the smallest value, I use a min-heap.

If I need the largest value, I use a max-heap.

The goal is always to make removing unwanted candidates as cheap as possible.

---

## PPT 4 — Heap vs Sorting

A very common mistake is using sorting when a heap would be better.

Sorting gives a complete order and costs O(n log n).

But many interview problems don't need a complete order.

For example:

Finding the top 10 largest values in a million numbers.

Using sorting processes everything.

Using a heap of size 10 only keeps the candidates that matter.

This reduces complexity to O(n log k).

So the difference is:

Sorting gives a full order once.

Heap continuously maintains the best candidates.

---

## PPT 5 — Top K Pattern

The most common heap pattern is Top K.

Examples include:

* Kth Largest Element
* Top K Frequent Elements
* K Closest Points

The standard solution is to maintain a heap of size K.

For K largest elements, we use a min-heap.

The heap stores the current K best candidates.

Whenever the heap grows beyond K, we remove the smallest element.

At the end, the heap contains exactly the K values we care about.

The key idea is:

**Keep only the candidates that still matter.**

---

## PPT 6 — K-Way Merge Pattern

The second major heap pattern is K-Way Merge.

This appears in problems like:

* Merge K Sorted Lists
* Kth Smallest Element in a Sorted Matrix

The idea is very elegant.

Each sorted source contributes one candidate to the heap.

We repeatedly take the smallest candidate and then add the next element from the same source.

The heap size never exceeds K.

This gives us O(N log K) complexity.

The key insight is:

Instead of sorting everything again, we only compare the current candidates from each source.

---

## PPT 7 — Two Heaps for Streaming Median

One of the most famous heap problems is Find Median from Data Stream.

The solution uses two heaps.

A max-heap stores the smaller half of the numbers.

A min-heap stores the larger half.

We keep them balanced so their sizes differ by at most one.

When new numbers arrive, we insert and rebalance.

This allows insertion in O(log n) and median lookup in O(1).

The key idea is:

Two heaps divide the data into two balanced halves.

---

## PPT 8 — Scheduling Problems

Heap is also extremely common in scheduling problems.

Examples include:

* Meeting Rooms
* Task Scheduler
* CPU Scheduling

The general pattern is:

Sort events by time.

Push available candidates into a heap.

Then repeatedly choose the best available candidate.

For Meeting Rooms, the heap stores room end times.

For CPU scheduling, the heap stores available jobs.

In both cases, the heap helps us continuously choose the next best option.

---

## PPT 9 — Common Mistakes

There are several common heap mistakes.

First, using sorting when the candidate set changes dynamically.

Second, maintaining the wrong heap size in Top K problems.

Third, forgetting to use negative values when simulating a max-heap.

Fourth, forgetting tie-breakers when storing custom objects in Python tuples.

And finally, forgetting lazy deletion in problems that require removing arbitrary elements.

The important thing to remember is:

Most heap bugs come from managing heap contents, not from heap operations themselves.

## PPT 10 — Senior-Level Explanation and Closing Insight

At a senior level, I would explain heap like this.

A heap is a data structure used to maintain a dynamic candidate set and efficiently retrieve the highest-priority candidate.

When solving a heap problem, I focus on five questions:

What is the priority?

Do I need a min-heap or max-heap?

What should each heap entry store?

How large should the heap be?

And why is heap better than sorting?

The final insight is:

**Heap is not about sorting data.**

**Heap is about maintaining the right candidates and always being able to choose the next best one efficiently.**

If you can explain the priority, the heap contents, the heap size, and the complexity tradeoffs, then you understand Heap and Priority Queue at an interview-ready level.
